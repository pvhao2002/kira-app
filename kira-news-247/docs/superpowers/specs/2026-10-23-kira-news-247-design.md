# Kira News 247 — design

Status: decided in goal mode (user asked to build without pausing for questions). Every "call" below is the
builder's decision, not something the user confirmed; review them first.

## Intent

A Vietnamese news site whose articles are written daily by an AI agent (ChatGPT Codex driving a browser with its
computer-use skill). The owner only logs in, reads drafts, approves them or leaves comments; the agent picks the
comments up and revises. Public pages must rank well (SEO) and every read records the reader's ipinfo data.

## Hard constraints (from the user)

- New module `kira-news-247`, Java 25 backend (modern syntax), Angular 21 frontend (Signals, `httpResource`, RxJS).
- Oracle Autonomous Database.
- shadcn/ui look → Angular port **spartan-ng** (brain + helm) on Tailwind v4.
- BE ↔ FE payloads are **protobuf** (`application/x-protobuf`), not JSON.
- Client calls ipinfo when a reader opens an article and the data is stored.
- Admin site; review workflow optimised for an AI agent operating the UI.

## Layout

```
kira-news-247/
  proto/kira/news/v1/news.proto     single source of the API contract
  kira-news-247-service/            Spring Boot 3.5, Java 25, Oracle, Flyway
  kira-news-247-ui/                 Angular 21 SSR app (public site + /admin)
  docs/AI-AGENT-PLAYBOOK.md         prompt/instructions to give Codex
  docker-compose.yml                local Oracle Free (gvenzl/oracle-free) for dev
```

## Backend

- Package per capability: `article`, `category`, `review` (comments), `reading` (read events), `identity` (auth),
  `seo` (sitemap/rss/robots), `shared` (protobuf error handler, markdown).
- Protobuf: `protobuf-java` generated by `io.github.ascopes:protobuf-maven-plugin` (downloads `protoc`, no local
  install). Spring's built-in `ProtobufHttpMessageConverter` does the wire format; controllers take/return generated
  messages. Errors are an `ApiError` message with a stable code.
- Persistence: Spring Data JPA on Oracle (`ojdbc11` + `oraclepki` for ADB wallets), Flyway
  (`flyway-database-oracle`). IDs are identity `NUMBER`; body is `CLOB`; optimistic `version` column.
- Article body is Markdown; the server renders sanitized HTML with commonmark-java (raw HTML escaped) and stores both.
  Call: Markdown, because an agent can type/paste it reliably; rich-text editors are flaky under computer use.
- Java 25 features used where they fit naturally: records, sealed interfaces + pattern-matching `switch` for the
  workflow decision, unnamed variables `_`, virtual threads (`spring.threads.virtual.enabled`).

### Workflow (the core)

States: `DRAFT → IN_REVIEW → (CHANGES_REQUESTED ↔ IN_REVIEW) → PUBLISHED → ARCHIVED`, plus `REJECTED`.

| Action | Who | From | To |
|---|---|---|---|
| SUBMIT | editor (AI) or admin | DRAFT, CHANGES_REQUESTED | IN_REVIEW |
| REQUEST_CHANGES | admin | IN_REVIEW | CHANGES_REQUESTED |
| PUBLISH | admin | IN_REVIEW | PUBLISHED (sets `published_at`) |
| REJECT | admin | IN_REVIEW, CHANGES_REQUESTED | REJECTED |
| UNPUBLISH | admin | PUBLISHED | ARCHIVED |

- Editing content is allowed in DRAFT and CHANGES_REQUESTED, and by the admin in IN_REVIEW and PUBLISHED (call: lets
  the owner fix a typo on a live article without a review round). The slug is frozen once an article has been
  published, so public URLs never change. Each save of content
  writes an `ARTICLE_REVISION` snapshot so the reviewer can see what the AI changed.
- Comments belong to an article, record the revision number they were written against, and can be resolved
  (by the editor after fixing, or by the admin). Admin "request changes" requires at least one open comment.
- Roles: `ADMIN` (owner: everything), `EDITOR` (AI account: create, edit, submit, reply/resolve comments; cannot
  publish). Enforced server-side.
- Auth: server session cookie + Spring Security CSRF cookie (`XSRF-TOKEN`), which Angular's `HttpClient` sends
  natively. Call: sessions over JWT — one server, browser-only clients, nothing to refresh.
- Users: bootstrapped from env (`NEWS_ADMIN_*`, `NEWS_EDITOR_*`) on first start; BCrypt hashes.

### Reads (ipinfo)

- Browser only (never during SSR): on article view, call `https://ipinfo.io/json?token=…` once per browser session
  (cached in `sessionStorage`), then `POST /api/v1/public/reads` with a `ReadEvent` protobuf.
- Server stores ipinfo fields (ip, city, region, country, loc, org, postal, timezone) plus server-observed remote
  IP, user agent, referrer, visitor/session ids; validates lengths; increments the article view counter.
- Admin dashboard shows totals, top articles, recent reads with location.

### SEO

- Angular SSR (`@angular/ssr`, Express) for every public route; slug URLs `/tin/{slug}`, `/chuyen-muc/{slug}`,
  `/tim-kiem`. Per-page `<title>`, description, canonical, Open Graph/Twitter tags, `NewsArticle` + `BreadcrumbList`
  JSON-LD. HTTP transfer cache avoids the double fetch on hydration.
- Backend serves `/sitemap.xml`, `/news-sitemap.xml` (Google News, last 48h), `/rss.xml`, `/robots.txt`; the SSR
  server proxies them. Admin routes are `noindex` and disallowed in robots.

## Frontend

- Angular 21 standalone, zoneless, Signals; data via `httpResource.arrayBuffer(...)` with a `parse` that decodes
  protobuf (`@bufbuild/protobuf` v2 + `protoc-gen-es`); mutations through an `HttpClient`/RxJS `ProtoApi`.
- spartan-ng helm components (button, input, textarea, label, badge, card, separator, skeleton…).
- Design system: `design-system/kira-news-247/MASTER.md` (ui-ux-pro-max). Call: background off-white instead of the
  suggested pink; Newsreader headings, Roboto body; red "breaking" primary, blue links; motion minimal.
- Admin pages: login, dashboard, review queue (tabs by status), article editor (Markdown + live preview + quick
  paste of front-matter), comments thread, revision viewer, categories, reads log.

### Agent-friendliness (computer use)

- Plain labelled inputs with stable `data-testid` and visible labels; no drag/drop, no hover-only controls.
- **Quick paste**: one textarea accepting `---\ntitle: …\nsummary: …\ncategory: …\ntags: a, b\ncover: …\nsources: …\n---\n<markdown>`
  that fills the whole form — the agent pastes one block instead of filling eight fields.
- "Việc cho AI" queue lists articles in CHANGES_REQUESTED with their open comments inline.
- `docs/AI-AGENT-PLAYBOOK.md` is the daily prompt for Codex.

## Non-goals (skipped, named)

Image upload (cover is a URL), scheduled publishing, reader accounts/comments, full-text Oracle Text index
(LIKE search on title/summary), i18n beyond Vietnamese, revision diff view (side-by-side text only).
